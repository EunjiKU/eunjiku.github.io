# 접근성 규칙 — publishing 스킬 §8 의 본문

> 이 파일은 `publishing` 스킬 §8 의 전체 규칙이다. SKILL.md 의 §8 은 요약과 이 파일로의 링크만 담는다.
> **판정 기준의 원본**이며, `a11y-check` 스킬은 이 기준을 실행하는 절차다. 폼·표·캐러셀·모달·링크 같은 접근성이 걸리는 작업을 할 때, 그리고 인증 대응 점검 때 연다.

## 8. 접근성 (A11y) — 전체 규칙

- 키보드 탐색이 가능하도록 포커스 스타일을 유지한다 (`outline`을 제거하지 않는다).
- 탭 UI에는 반드시 ARIA 속성을 적용한다 (`role`, `aria-selected`, `aria-controls`, `aria-labelledby`).
  > 국내 WA 인증 심사기관 일부는 탭에 ARIA role 을 쓰지 않고 `title="선택됨"` 방식을 요구한다. **인증 신청이 확정되면 심사기관 기준을 확인하고 `CLAUDE.md` 「프로젝트 설정」에 방식을 적는다.** 그 전까지는 표준 WAI-ARIA 를 따른다.
- **탭 모양이어도 패널을 바꾸지 않는 앵커(누르면 목록 · 페이지 안의 위치로 이동 — 카드 스와이퍼의 분야 탭 등)는 탭 ARIA 를 쓰지 않는다.** `role="tablist"` · `role="tab"` · `aria-selected` 는 짝이 되는 `tabpanel` 이 있는 탭에만 — 패널이 없으면 스크린리더가 "탭"으로 읽고 없는 패널을 기대한다. 앵커는 `<button>`(같은 페이지 `#id` 이동이면 `<a href>`) + `.is-active` + `aria-current="true"`, 묶음은 `role="group"` + `aria-label`.
- 색상 대비 비율은 WCAG 2.1 AA 기준(4.5:1) 이상을 유지한다.
- `aria-hidden="true"`는 장식 요소에만 사용한다.
- 화면에서 숨기고 스크린리더에만 읽힐 텍스트는 `common.css` 의 `.blind` 를 쓴다.

### 포커스 링 · Hover

**포커스 링은 `common/_utilities.scss`(「4. 접근성·공통 클래스」)의 전역 `:focus-visible` 한 줄이 그린다** (2px · offset 2px · `--color-border-focused`). 컴포넌트에서 `outline: none` 으로 지우지 않는다. 마우스 클릭에는 안 나오고 키보드 포커스에만 나온다 (`common/_reset.scss` 「포커스」).

- **입력 부품**(`.input` · `.select` · `.textarea` — 검색창도 `.input`)은 시안에 포커스 테두리(포커스 때 래퍼 테두리가 진해짐)가 있으면 **그 테두리가 포커스 표시다** — 래퍼에 `:focus-within` 테두리 색을 주고, 안쪽 `input` · `select` · `textarea` 는 `&:focus-visible { outline: none; }`. 링을 겹쳐 그리지 않는다. 안의 지우기 · 보기 · 검색 버튼은 전역 링 그대로. 시안에 포커스 테두리가 없으면 안쪽 outline 을 끄고 래퍼가 같은 링을 그린다 (`tools` 믹스인 `ring-to-wrapper` — 지우기 · 검색 버튼까지 감싸게).
- 부모가 `overflow: auto/hidden` 이면 링이 잘린다 — 부모에 `padding-block: 4px` + 같은 음수 `margin-block` 으로 자리를 내준다.

**`:hover` 를 쓰면 `:focus-visible` 도 같이 선언하고, 그 규칙을 `@media (hover: hover)` 로 감싼다.** 터치 기기는 탭한 요소에 hover 가 남아(뒤로 가기 후에도 카드가 반전된 채) 선택된 것처럼 보이기 때문이다. 터치 기기의 키보드 포커스는 전역 링이 표시하므로 hover 모양이 빠져도 포커스는 보인다.

- 기본 상태 선택자(`.is-active` · 기본 색)는 미디어쿼리 **밖**에 둔다 — 안에 넣으면 터치 기기에서 기본 상태가 사라진다.
- `:not(:hover)` 처럼 hover 를 빼는 조건, `:focus-within` 은 감싸지 않는다.
- 이 미디어쿼리는 브레이크포인트가 아니라 입력 장치 조건이라 「반응형은 파일 끝」 규칙과 무관하게 컴포넌트 바로 아래에 둔다.

```css
.tabs .tab:focus-visible,
.tabs .tab.is-active { color: var(--color-{탭 선택 글자}); }
@media (hover: hover) {
  .basic-btn-outlined:hover,
  .basic-btn-outlined:focus-visible { background: var(--color-{버튼 외곽선 hover 면}); }
  .tabs .tab:hover { color: var(--color-{탭 선택 글자}); }
}
```

**포커스를 받는 요소 자체에 `mask` 를 걸지 않는다.** `mask` 는 outline 까지 잘라 포커스 표시가 아이콘 모양으로 줄거나 사라진다. 아이콘 mask 는 `::before` 에 건다 (`assets.md` 「아이콘 — SVG 파일 + mask」).

**PC 폭의 터치 기기** — hover 로 여는 메뉴(GNB 2depth 등)는 iPad 가로·터치 노트북에서 열 방법이 없다. 닫힌 상태의 첫 탭은 이동 대신 열기로 받고(`pointerdown` 의 `pointerType`), 바깥 탭으로 닫는다 (구현 예 — `common.js` 「GNB」).

### Label + Input 매칭

`<label>` 과 `<input>`/`<select>`/`<textarea>` 가 한 셋으로 있으면 `for`/`id` 로 반드시 연결한다. 레이블이 시각적으로 없는 컨트롤(검색 인풋, 아이콘 버튼)은 `aria-label` 을 준다.

### KWCAG 2.2 인증 대응 규칙

웹 접근성 품질인증(WA 인증마크)은 KWCAG 2.2 검사항목으로 **실물 페이지**를 심사한다. 아래는 심사에서 자주 지적되는 항목을 규칙화한 것이다. **신규 페이지에 전부 적용**하고, 기존 페이지는 요청 시 소급한다.

#### 인식의 용이성

- **대체 텍스트** — 의미 있는 `<img>` 는 내용을 구체적으로 서술하는 `alt`, 장식 이미지는 `alt=""`. **`@` 더미 이미지는 `alt=""`**(`assets.md` 「에셋 네이밍」) · **사진 블록(`.swap-visual` · `.parallax-visual`) 이미지도 `alt=""`** — 분위기용 비주얼이다. 단 이미지가 버튼 · 링크의 유일한 내용이면 그 버튼에 이름(`aria-label` · `.blind`)을 따로 둔다. CSS background 로 처리한 아이콘 버튼/링크는 `aria-label` 필수.
- **에디터 관리 영역(상세 본문 `.post-body`)에는 ARIA 를 달지 않는다** — 관리자가 에디터로 채우는 자리라 `aria-labelledby` · `id` 연결이 저장 때 빠지거나 어긋난다. `.post-body` 바로 아래 제목(`.sec-head`) + 에디터 본문(`.editor`) 만 두고, `<section>` 으로 한 번 더 감싸지 않는다.
- **색에 무관한 인식** — 상태(마감/진행, 오류, 선택됨)를 **색만으로 구분하지 않는다.** 텍스트 레이블, 아이콘, 굵기 등 색 외의 단서를 병행한다. (예: 마감 카드는 회색 톤 + "마감" 라벨)
- **명확한 지시사항** — "오른쪽 버튼", "빨간 항목"처럼 모양·위치·색에만 의존하는 안내 문구를 쓰지 않는다.
- **멀티미디어** — 영상에는 자막(또는 대본)을 함께 제공한다. 배경음 자동 재생 금지.

#### 운용의 용이성

- **반복 영역 건너뛰기** — 모든 페이지 `<body>` 최상단에 스킵 링크를 넣는다. 스타일은 `common.css` 의 `.skip` (포커스 시에만 노출).

  ```html
  <body>
    <a href="#content" class="skip">본문 바로가기</a>
    …
    <main id="content">
  ```

- **모든 기능의 키보드 조작 보장** — 마우스·터치 전용 기능을 만들지 않는다. **드래그/스와이프로만 조작되는 UI(캐러셀·슬라이더)는 키보드 대안을 함께 제공한다.** Swiper 캐러셀은 `keyboard` · `a11y` 를 켜고 이전/다음 버튼 또는 페이지네이션을 둔다 — 필요한 빌드와 탭 스와이퍼 예외는 `javascript.md` 「모션」.
- **자동 변경 콘텐츠의 정지 기능** — `autoplay` 캐러셀/배너에는 **정지·재생 버튼과 이전/다음 컨트롤을 반드시 함께 제공한다.** 정지 수단 없는 자동 롤링은 금지.
- **터치 타깃 크기** — 버튼·링크·탭 아이템은 **최소 44×44px** (600 폭 기준 실측). 시각적 크기가 작아야 하면 투명 패딩이나 `::after` 로 히트 영역만 넓힌다.
- **깜빡임 제한** — 초당 3회 이상 깜빡이는 콘텐츠를 만들지 않는다.
- **시간 제한** — 자동 로그아웃 등 시간 제한 기능은 연장 수단을 제공한다.
- **페이지 제목과 위계** — 고유한 `<title>`, 페이지당 `<h1>` 하나, 건너뜀 없는 h2~h3 위계 (§9 와 동일). 숨김 제목(`.blind` heading)으로 위계를 채우지 않는다 — 보이는 제목만 (`markup.md` 「문서 구조」).
- **링크 텍스트** — "더보기", "클릭" 같은 맥락 없는 링크 텍스트를 피하고, 불가피하면 `aria-label` 로 대상을 명시한다. (`aria-label="공지사항 더보기"`)

#### 이해의 용이성

- **기본 언어** — `<html lang="ko">`.
- **사용자 요구에 따른 실행** — 새 창으로 여는 링크는 사전에 알린다 (`target="_blank" rel="noopener"` + `title="새 창 열림"` 또는 aria-label 에 명시 — `rel="noopener"` 는 열린 창이 이 페이지를 조작하지 못하게). **`<select>` 의 `onchange` 로 페이지를 자동 이동시키지 않는다** — 확인 버튼을 둔다.
- **오류 정정** — 폼 검증 오류는 (1) 어떤 입력이 왜 틀렸는지 텍스트로 알리고 (2) 해당 입력과 `aria-describedby` 로 연결하며 (3) 색상만으로 표시하지 않는다.

  ```html
  <input type="text" id="userPhone" aria-describedby="phoneError" aria-invalid="true" />
  <div id="phoneError" class="help">연락처는 숫자만 입력해 주세요.</div>
  ```

  오류 문구는 **태그 하나에 문구를 바로** 넣어, 오류가 나면 태그째 넣고 풀리면 태그째 뺀다 (안에 한 겹 더 감싸지 않는다 — 개발이 바깥만 남기고 안만 바꾸면 빈 칸이 자리를 차지한다). 문구 칸 위 간격은 그 태그의 마진으로 줘서 태그가 빠지면 간격도 빠지게 한다. 빈 칸을 `:empty` · `:not(:has(*))` 로 숨기지 않는다 — 개발이 그 안에 무엇(스크립트 · 템플릿 태그)을 넣을지 모른다. 글자 수처럼 늘 있는 정보와 한 줄이면 감싸는 줄(`.info`)은 두고 문구 태그만 넣고 뺀다.

#### 견고성

- **`id` 중복 금지** — 한 페이지 안에서 같은 `id` 를 두 번 쓰지 않는다.
- **마크업 문법** — 태그 열고 닫기, 속성 중복, 잘못된 중첩이 없어야 한다. `a11y-check` 스킬의 자동 점검으로 확인한다.

### 색상 대비 관리

#### 대비 미달 색상 — 프로젝트마다 표로 관리

실측 결과 WCAG AA(4.5:1) 미달인 조합은 **`PROJECT.md` 「대비 미달 색상」 표**에 모은다. 표에 오른 조합은 **본문·레이블 등 정보성 텍스트에 쓰지 않고**, 디자이너 협의 안건으로 유지한다. 대형 텍스트(24px 이상 또는 18.66px 볼드)는 3:1 까지 허용한다.

| 조합 | 실측 대비 | 비고 |
| --- | --- | --- |
| `#글자색` (토큰명) / `#배경색` (쓰는 곳) | 0.00 | 어디에 몇 px 로 쓰는지 · 대형 텍스트 허용 여부 · 협의 상태 |

- 대비는 `a11y-check` ⑤ 의 스크립트로 계산한다.
- 통과한 조합 중 헷갈리기 쉬운 것은 표 아래 "통과 참고" 한 줄로 남긴다.
- disabled 컨트롤의 글자는 WCAG 대비 요건에서 제외된다.
- 토큰 값이 바뀌면 재계산한다.

#### 신규 색상 추가 시 대비 검증 필수

`_tokens.scss` 에 텍스트용 색상 토큰을 추가하거나 새 색 조합을 쓸 때는 **커밋 전에 대비를 계산**한다. 4.5 미만이면 사용을 보류하고 `PROJECT.md` 「대비 미달 색상」 표에 추가한다. (토큰 전체는 UI 가이드의 Color 페이지 `list/color.html` 에서 본다.)

### 접근성 검증 — a11y-check 스킬로 수행

페이지를 완성(또는 큰 수정)하면 완료 보고 전에 **`a11y-check` 스킬**의 점검 절차를 수행한다. 자동 점검 스니펫, 대비 계산, 실행 순서, 보고 포맷은 그 스킬이 관리한다. 이 문서(§8)는 **판정 기준의 원본**이고, 스킬은 그 기준을 실행하는 절차다.

### 접근성 검수 체크리스트

- [ ] 스킵 링크 존재 + 포커스 시 노출
- [ ] `<html lang="ko">`, 고유한 `<title>`, `<h1>` 1개 + 제목 위계 · 숨김 제목 없음
- [ ] 모든 이미지 `alt` / 아이콘 버튼 `aria-label`
- [ ] `<table>` 에 `<caption>` + `<th scope>`
- [ ] GNB 현재 메뉴 `aria-current` — 현재 2depth 만 `page` · 1depth 는 `true`
- [ ] 전체 화면 레이어가 열리면 바깥 `inert`, 닫으면 여는 버튼으로 포커스 복귀 · Esc 로 포커스를 잃지 않는다
- [ ] `<label>`-`<input>` `for`/`id` 연결, 오류 메시지 `aria-describedby` 연결
- [ ] 텍스트 대비 4.5:1 이상 (`PROJECT.md` 「대비 미달 색상」 조합 미사용)
- [ ] 상태·오류를 색 이외의 단서로도 표현
- [ ] Tab 키만으로 전 기능 조작 + `:focus-visible` 표시
- [ ] 캐러셀: 키보드 조작 가능, autoplay 시 정지 버튼
- [ ] 터치 타깃 44×44px 이상
- [ ] 새 창 링크 사전 알림, `onchange` 자동 실행 없음
- [ ] 중복 `id` 없음
- [ ] 모션이 있으면 `prefers-reduced-motion` 분기
