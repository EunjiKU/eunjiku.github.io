# rem 기준 방식 비교 — 프로젝트 시작 시 선택

> `publishing` §7 「단위」에서 링크한다. 루트 글자 크기는 **프로젝트 시작 시 한 번 고르고** `CLAUDE.md` 「프로젝트 설정」의 「루트 글자 크기」에 적는다. 도중에 바꾸면 모든 rem 값을 다시 계산해야 한다 (§3 전환 절차).

## 선택 기준

- **기본값은 (A) vw 반응형이다.** SI 프로젝트의 기존 자산(`_reset.scss` 등)이 이 방식인 경우가 많고, 기존 자산과 같은 페이지에 섞이면 루트 선언이 하나여야 하기 때문이다.
- **단 (A) 는 WCAG 1.4.4(텍스트 크기 조정)를 만족하지 못한다.** 루트가 vw 라 브라우저 글자 크기 설정을 키워도 글자가 커지지 않는다. 화면 폭이 줄면 글자도 줄어서, 1440 모니터에서 16px 본문이 12px 로 보인다.
- **접근성 인증(WA 인증마크 등)이 필요한 프로젝트는 (B) 또는 (C) 를 고른다.** 둘 다 루트를 `%` 로 둬서 브라우저 설정을 따른다.
- 고른 방식과 이유를 `CLAUDE.md` 「루트 글자 크기」에 한 줄로 적는다. 기존 자산이 (A) 인데 (B)·(C) 를 고르면 §3-4 의 충돌을 먼저 확인한다.

## 1. 방식 비교

| 항목 | (A) vw 반응형 — 기본값 | (B) 100% (16px) | (C) 62.5% (10px) |
| --- | --- | --- | --- |
| 루트 | `html { font-size: 0.052vw }` + 1024↓ `0.13vw` + 600↓ `0.256vw` | `html { font-size: 100% }` | `html { font-size: 62.5% }` |
| 1rem 의 크기 | 화면 폭에 비례. 1920 에서 1px, 1440 에서 0.75px, 1024 에서 1.33px | 브라우저 설정에 비례. 기본 16px | 브라우저 설정에 비례. 기본 10px |
| 시안 숫자 → 코드 | 그대로 (`24px` → `24rem`) | ÷16 (`24px` → `1.5rem`) | ÷10 (`24px` → `2.4rem`) |
| 화면 폭을 줄이면 | 페이지 전체가 비율대로 축소 | 변하지 않음. 브레이크포인트에서 값만 재선언 | 〃 |
| 브라우저 글자 설정을 키우면 | **무시됨** (WCAG 1.4.4 미충족) | 페이지 전체가 커짐 | 페이지 전체가 커짐 |
| 1px 보더 | px 로 따로 쓴다 | px | px 권장 (`.1rem` 이면 확대 시 같이 두꺼워짐) |
| 반응형 구현 | 루트 재선언 3번. 중간 폭은 자동 | 브레이크포인트마다 값 재선언 | 〃 |
| 시안과 1:1 인 폭 | 루트를 맞춘 지점(1920 · 768 · 390)만 | 어떤 폭이든 | 〃 |

- `html { font-size: 16px }` · `10px` 처럼 루트를 **px 로 고정하면 (A) 와 같이 브라우저 설정을 무시한다.** (B)·(C) 는 반드시 `%` 로 쓴다.
- (C) 는 시안 숫자 환산이 쉬워 국내 에이전시·금융·공공 사이트에서 가장 흔하다. (B) 는 환산이 번거롭지만 브라우저 기본값 그대로라 서드파티 위젯과 충돌이 적다.

한 줄 요약

- (A) — 화면 폭에 맞춰 **페이지 전체를 줌** (시안 재현 우선)
- (B)·(C) — 사용자 글자 설정에 맞춰 **페이지 전체를 줌** (접근성 우선)

## 2. 단위 적용 범위 — (B)·(C) 를 고를 때

| 속성 | 단위 |
| --- | --- |
| `font-size` · 폭 · 높이 · 간격 · 라운드 · 아이콘 크기 | rem (시안 ÷16 또는 ÷10) |
| `line-height` | 단위 없음 |
| `letter-spacing` | em |
| 보더 · 아웃라인 · 그림자 · 브레이크포인트 · `.blind` · `.skip` | px |

## 3. (A) 에서 (C) 로 바꿀 때 — 전환 절차

이미 (A) 로 작업한 산출물을 옮기는 경우다. 손대는 것은 공통 CSS 와 문서다. (B) 는 같은 절차에서 ÷10 을 ÷16 으로, `62.5%` 를 `100%` 로 바꾼다.

### 3-1. CSS

고치는 것은 `scss/` 소스이고, 끝나면 `npm run scss` 로 `common.css` 를 다시 만든다 (`css/` 는 손대지 않는다).

1. `common/_base.scss`
   - `html { font-size: 0.052vw }` → `html { font-size: 62.5% }`
   - 파일 끝의 `@include mo { html { font-size: 0.13vw } }` · `@include sm { html { font-size: 0.256vw } }` 블록 삭제
   - 상단 "rem 기준" 주석을 62.5% 설명으로 교체
2. `common/_tokens.scss` — `:root` 와 파일 끝 재선언 안의 모든 rem 토큰을 **÷10**. 예: `--font-b3-reg: 400 16rem / 1.6 …` → `400 1.6rem / 1.6 …`
3. 나머지 부분 파일(`common/` 골격 · `components/` · `_tools.scss`) — 모든 rem 값을 ÷10. 예: 간격 리터럴 `24rem` → `2.4rem`. 보더·아웃라인·`box-shadow`·`@media` 폭·구분선 `width: 1px` 은 px 그대로

```bash
# 산출물 루트에서. 보더·아웃라인·미디어쿼리 줄은 건드리지 않는다 (components/ 는 수동 확인 후). 끝나면 npm run scss
for f in common/scss/_tools.scss common/scss/common/*.scss common/scss/components/*.scss; do
  [ -f "$f" ] && node -e '
const fs=require("fs");const f=process.argv[1];
const x=s=>s.replace(/(-?[\d.]+)rem\b/g,(m,n)=>String(Math.round(n/10*1000)/1000)+"rem");
fs.writeFileSync(f,fs.readFileSync(f,"utf8").split("\n").map(l=>/^\s*(border|outline|box-shadow|@media)/.test(l)?l:x(l)).join("\n"));
' "$f"
done
```

경로는 `CLAUDE.md` 「프로젝트 설정」의 공통 에셋 위치에 맞춘다.

### 3-2. 문서

- `CLAUDE.md` 「루트 글자 크기」 — `html { font-size: 62.5% }` (1rem = 10px), 길이 전부 rem(시안 ÷10), 보더·아웃라인·그림자만 px. 기존 자산의 리셋 CSS 를 같은 페이지에 로드하지 않는다 (루트 선언 충돌)
- 프로젝트 문서에 시안 px → rem 환산을 적어 둔 곳이 있으면 ÷10 으로 고친다. 스킬 본문은 「루트 글자 크기」를 보도록 되어 있어 고치지 않는다

### 3-3. 검증

`_template.html` 을 로컬 서버로 열고 아래를 실측한다. 전환 전 (A) 에서 같은 표를 먼저 채워 두고 비교한다.

| 상황 | 본문 | h1 | GNB 높이 | GNB 보더 | 가로 오버플로 |
| --- | --- | --- | --- | --- | --- |
| 1920, 기본 글자 | (A) 와 같음 | 〃 | 〃 | 1px | 0 |
| 1920, 개발자도구에서 `html { font-size: 75% }` (사용자 확대 시뮬레이션) | 1.2배 | 1.2배 | 1.2배 | 1px | 0 |
| 1024 · 600 | 브레이크포인트 재선언값 | 〃 | 〃 | 1px | 0 |

기본 상태의 크기가 (A) 와 같고, 확대 시 보더만 1px 로 남으면 성공이다.

### 3-4. 개발 이전 시 주의

백엔드 공통 레이아웃이 기존 리셋 CSS(vw 루트)를 전역으로 넣는지 확인한다. 같은 페이지에 루트 선언이 둘이면 한쪽 치수가 전부 깨진다. 넣는다면 신규 `common.css` 가 뒤에 로드되게 하거나, 신규 페이지에서 기존 리셋 CSS 를 뺀다.
